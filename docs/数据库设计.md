# 数据库设计

> 项目：基于 MongoDB 的简化版在线问卷系统
> 数据库名：`survey_system`
> 文档版本：v2（第二阶段：新增"题库 / 可复用题目"，见 §4.6）

---

## 1. 设计目标与原则

1. **不把所有数据塞进一个集合**：用户、问卷、题目、填写、答案是 5 个独立的业务实体，独立成集合更利于查询、统计与扩展。
2. **谨慎使用冗余**：仅在确实为了查询性能/统计便利时冗余，否则一律引用。
3. **业务规则存数据，不写死代码**：跳转规则（`next_rule`）、校验规则（`validation`）都以文档形式存在集合里，后端只负责解释执行。
5. **数据可回溯**：每一次提交都生成 `responses + answers` 快照，统计从原始答案重算，不在 `surveys` 中累加预计算数字。

---

## 2. 为什么不使用关系型数据库

| 维度 | 关系型 | MongoDB（本项目） |
|---|---|---|
| 问卷结构 | 题目类型与字段差异大 → `questions` 表需要 EAV 或 JSON 列 | 直接以文档嵌套（`options[]`、`validation{}`）表达，结构灵活 |
| 跳转规则 | 需要一张 `question_branches` 关联表 | 直接嵌入 `questions.next_rule`，天然与题目同生命周期 |
| 答案 | 单/多选、文本、数字类型差异大，关系型要么拆 3 张表，要么用 JSON 列 | `value` 字段允许任意结构，统计时按题型分桶 |
| 统计聚合 | 多表 JOIN + 视图 | `$lookup` + 聚合管道一次性出结果 |
| Schema 演进 | ALTER TABLE 成本高 | 文档模型对新增题型友好，第二阶段扩展成本低 |

> 结论：本系统的核心实体（题目与答案）天然是"半结构化"的——题目类型决定字段，答案类型决定值类型——文档型数据库比关系型更贴合。

---

## 3. 集合（Collection）一览

| 集合 | 主要字段 | 一句话说明 |
|---|---|---|
| `users` | `username`, `password_hash`, `created_at` | 系统用户 |
| `surveys` | `title`, `owner_id`, `status`, `token`, `deadline` | 问卷元数据 |
| `questions` | `survey_id`, `type`, `title`, `options`, `validation`, `next_rule`, `order`, `bank_ref` | 问卷中的题目 |
| `responses` | `survey_id`, `user_id`, `submitted_at`, `is_anonymous` | 一次填写记录 |
| `answers` | `response_id`, `question_id`, `value` | 单题作答 |
| `bank_questions` | `root_id`, `version`, `parent_id`, `title`, `owner_id`, `visibility`, `shared_with`, `in_bank` | 题库题目（一个文档 = 一个版本） |

```
users ─< surveys ─< questions ─< answers
            │           │  │
            │           │  └─ bank_ref ─→ bank_questions
            └─< responses ─< answers

bank_questions（题目家族）：
  v1 ──parent_id──→ v2 ──parent_id──→ v3
  └──────────── root_id 相同 ────────────┘
```

引用关系：
- `surveys.owner_id → users._id`
- `questions.survey_id → surveys._id`
- `responses.survey_id → surveys._id`
- `responses.user_id → users._id`（必填：所有填表者均需先登录）
- `responses.is_anonymous` 冗余自 `surveys.allow_anonymous`，供统计页判断是否展示用户名
- `answers.response_id → responses._id`
- `answers.question_id → questions._id`
- `questions.bank_ref.version_id → bank_questions._id`（可空：普通新建的题目没有该字段）
- `questions.bank_ref.root_id → bank_questions.root_id`（可空：用于跨问卷统计与"被哪些问卷使用"反查）
- `bank_questions.parent_id → bank_questions._id`（可空：初始版本无父版本）
- `bank_questions.root_id → bank_questions._id`（自引用：家族 ID）
- `bank_questions.owner_id → users._id`
- `bank_questions.shared_with[] → users._id`

## 4. 各集合详细设计

### 4.1 `users`

```json
{
  "_id": ObjectId,
  "username": "pck",                    // 唯一，登录用
  "password_hash": "<bcrypt>",          // 不存明文
  "created_at": ISODate
}
```

**约束**
- `username` 全局唯一、长度 3-32、规则 `^[A-Za-z0-9_]+$`
- `password_hash` 使用 `bcrypt`，cost=12

---

### 4.2 `surveys`

```json
{
  "_id": ObjectId,
  "title": "大一新生调研",
  "description": "用于了解新生学习习惯",
  "allow_anonymous": false,             // 是否允许匿名填写
  "owner_id": ObjectId,                  // → users._id
  "status": "draft",                     // draft / published / closed
  "token": "x9k2Aa",                     // 发布后生成的访问 token（短码）
  "deadline": ISODate | null,             // 截止时间，可空
  "created_at": ISODate,
  "published_at": ISODate | null
}
```

**约束**
- `status` 仅在三个枚举值之间转换：`draft → published → closed`（不可逆）
- `token` 全局唯一、6-12 位字母数字混合
- `deadline` 仅在 `published` 后生效；过期后填写接口返回 410

---

### 4.3 `questions`

```json
{
  "_id": ObjectId,
  "survey_id": ObjectId,
  "order": 1,                            // 在问卷中的顺序号，从 1 开始
  "type": "single",                      // single | multi | text | number
  "title": "你的性别",
  "required": true,
  "options": ["男", "女", "其他"],        // 仅 single/multi 使用
  "validation": { ... },                  // 见 §5
  "next_rule": { ... },                   // 见 §6
  "bank_ref": { ... },                    // 见 §4.6.2，选填
  "created_at": ISODate
}
```

**约束**
- `order` 在同一 `survey_id` 内唯一，从 1 起递增
- `options` 仅 `single`/`multi` 类型必须有，且不能为空
- `validation` 结构随 `type` 不同而不同（见 §5）
- `next_rule` 默认 `{ "mode": "default", "fallback": "next" }`，跳转规则见 §6
- `bank_ref` 只做"溯源 + 反查"用；**题目内容仍以本集合中的快照为准**，题库后续如何修改都不会回写这里（需求三）

---

### 4.4 `responses`

```json
{
  "_id": ObjectId,
  "survey_id": ObjectId,
  "user_id": ObjectId,                    // 必填：填表者必须先登录
  "is_anonymous": false,                  // 冗余自 surveys.allow_anonymous，决定统计是否展示用户名
  "submitted_at": ISODate,
  "answer_path": [1, 3, 5, 7],           // 实际走过的题目 order 序列，便于审计
  "duration_ms": 12345                   // 可选，填写耗时
}
```

**约束**
- **填表前必须登录**：API 在 `POST /surveys/{id}/submit/start` 强制要求 JWT，`user_id` 永远非空（不再依赖"匿名填表时不传 user_id"的设计）。
- 允许同一用户在同一问卷下多次提交（除非问卷设置禁止，第一阶段不实现）
- `is_anonymous` 在填写开始时从 `surveys.allow_anonymous` 复制而来，用于统计页决定是否展示用户名（`true` → 显示"匿名"，`false` → 展示真实 `username`）。
- `answer_path` 由后端在跳转时记录，不依赖前端。

---

### 4.5 `answers`

```json
{
  "_id": ObjectId,
  "response_id": ObjectId,
  "question_id": ObjectId,
  "value": <any>                         // 类型见下表
}
```

`value` 形态与 `type` 对应：

| `question.type` | `value` 形态 | 示例 |
|---|---|---|
| `single` | string（选项文本） | `"女"` |
| `multi` | array of string | `["苹果","西瓜"]` |
| `text` | string | `"我经常..."` |
| `number` | number | `27` |

---

### 4.6 `bank_questions`（第二阶段：题库 / 可复用题目）

**一个文档 = 一个题目版本。** 同一道题的所有版本构成一个"题目家族"，用 `root_id` 串起来；
`parent_id` 记录"这个版本是从哪个版本改过来的"（需求四/五）。

```json
{
  "_id": ObjectId,                        // 版本 ID
  "root_id": ObjectId,                    // 题目家族 ID（v1 的 _id，后续版本沿用）
  "version": 2,                           // 家族内从 1 递增
  "parent_id": ObjectId,                  // 派生来源版本（v1 为 null）
  "title": "你的年龄",
  "type": "single",
  "options": ["18-25", "26-35", "36-45"],
  "required": true,
  "validation": {},
  "owner_id": ObjectId,                   // → users._id，拥有者（只有拥有者能改/共享/删）
  "visibility": "private",                // private | public
  "shared_with": [ObjectId],              // → users._id，被共享的用户
  "tags": ["人口学"],
  "in_bank": true,                        // 是否已加入题库（需求七）
  "note": "新增了 26-35 岁选项",            // 本次改动的说明
  "created_at": ISODate,
  "updated_at": ISODate,
  "deleted_at": ISODate | null            // 软删除标记
}
```

**约束**
- `root_id` + `version` 唯一（唯一索引 `uniq_bank_root_version`）
- 修改题目**不原地覆盖**，而是插入一个新版本文档（需求三/五）
- 已被问卷引用的版本不允许删除（否则问卷里的题目会失去来源）
- `visibility = "public"` 时所有用户可见；否则仅 `owner_id` 与 `shared_with` 中的用户可见
- 删除是软删除（`deleted_at`），`in_bank` 同时置为 false

#### 4.6.1 版本家族示意

```
root_id = R
┌──────────────┬──────────────┬──────────────┐
│ v1           │ v2           │ v3           │
│ _id = R      │ _id = B      │ _id = C      │
│ parent=null  │ parent = R   │ parent = B   │
│ "你的年龄"   │ "你的年龄？"  │ "你今年多大？"│
└──────────────┴──────────────┴──────────────┘
     │                │                │
     └────────────────┴────────────────┘
              同一 root_id → 视为同一道题
```

#### 4.6.2 `questions.bank_ref`（问卷里引用的题库来源）

```json
"bank_ref": {
  "root_id": ObjectId,       // 题库题目家族
  "version_id": ObjectId,    // 具体版本
  "version": 2,             // 冗余的版本号，便于展示
  "title_snapshot": "你的年龄" // 冗余的题干，便于历史数据可读
}
```

问卷题目是**快照**：加入问卷时把 `title/type/options/required/validation` 复制一份存进 `questions`，
之后题库怎么改都不会影响已存在的问卷（需求三）。`bank_ref` 只用于反查：
- 需求六："这个题被哪些问卷用了" → `questions.bank_ref.root_id`
- 需求八："跨问卷统计这个题" → `questions.bank_ref.root_id` → `answers.question_id`

## 5. `validation` 字段定义（存数据库，不写死）

```jsonc
// single（可只声明 required）
{ "required": true }

// multi：限制选项数量
{
  "min_count": 2,
  "max_count": 3,
  "exact_count": null                    // 与 min/max_count* 必须显式空值**，表示"恰好"
}

// text（少输入字 / 多输入字）
{ "min_len": 1, "max_len": 200 }

// number（最小/最大/是否整数）
{ "min": 0, "max": 120, "integer_only": true }
```

> 所有 `validation` 字段都可缺省；缺省时按题型默认（必答默认 false）。

## 6. `next_rule` 跳转规则（存数据库，不写死）

跳转引擎读取 `next_rule.mode` 决定执行哪种解释器；不匹配时走 `fallback`。

### 6.1 单选 `by_option`

```json
{
  "mode": "by_option",
  "branches": [
    { "when": "A", "goto": 5 },            // goto 用 order 号（题目顺序号），不用 _id
    { "when": "B", "goto": 3 }
  ],
  "fallback": "next"                      // next | end | <order>
}
```

### 6.2 多选 `by_contains`

```json
{
  "mode": "by_contains",
  "branches": [
    { "when_any": ["A", "B"], "goto": 4 },
    { "when_all": ["C"],      "goto": 6 }
  ],
  "fallback": "next"
}
```

### 6.3 数字 `by_range`

```json
{
  "mode": "by_range",
  "branches": [
    { "when": { "op": ">=", "value": 18 }, "goto": 5 },
    { "when": { "op": "<",  "value": 18 }, "goto": 7 }
  ],
  "fallback": "next"
}
```

### 6.4 默认 `default`

```json
{ "mode": "default", "fallback": "next" }
```

### 6.5 语义说明

- `goto` 引用题目的 `order` 号，而非 `_id`，让 JSON 更易读。
- `goto` 引用的 `order` 必须在同一 `survey_id` 内存在，否则后端在保存时拒绝（一致性校验）。
- `fallback`：`"next"` 表示 `order + 1`；`"end"` 表示问卷结束；`<order>` 表示跳到该题。
- 保存时做**成环检测**：把"显式 goto"与"fallback=next 的隐式前进"一起构成有向图，DFS 检测环，检测到环则拒绝保存。
- **前向引用允许**：跳转到尚未创建的题目（order 更大）不报错，方便先建骨架再逐题配置跳转。

## 7. 索引设计

| 集合 | 索引 | 用途 |
|---|---|---|
| `users` | `{ username: 1 }` unique | 注册查重、登录 |
| `surveys` | `{ owner_id: 1, created_at: -1 }` | "我的问卷"列表 |
| `surveys` | `{ token: 1 }` unique | 通过短码访问 |
| `surveys` | `{ status: 1, deadline: 1 }` | 过期/关闭筛选 |
| `questions` | `{ survey_id: 1, order: 1 }` unique | 按问卷读题、按 order 排序 |
| `questions` | `{ survey_id: 1, type: 1 }` | 按题型分组（统计） |
| `responses` | `{ survey_id: 1, submitted_at: -1 }` | 问卷提交列表 |
| `responses` | `{ survey_id: 1, user_id: 1 }` | "我的填写记录" |
| `answers` | `{ response_id: 1 }` | 拉取某次提交的完整答案 |
| `answers` | `{ question_id: 1 }` | 单题统计聚合 |
| `bank_questions` | `{ root_id: 1, version: 1 }` unique | 版本号唯一 + 版本历史排序 |
| `bank_questions` | `{ owner_id: 1, updated_at: -1 }` | "我创建的题目"列表 |
| `bank_questions` | `{ shared_with: 1 }` | "共享给我的"题目查询 |
| `bank_questions` | `{ in_bank: 1, updated_at: -1 }` | 题库视图（需求七） |
| `questions` | `{ bank_ref.root_id: 1 }` | 反查题目被哪些问卷使用 / 跨问卷统计（需求六、八） |
| `questions` | `{ bank_ref.version_id: 1 }` | 按具体版本反查问卷 |

## 8. 关键查询示例

### 8.1 问卷详情（问卷 + 题目）

```javascript
db.surveys.aggregate([
  { $match: { _id: ObjectId("...") } },
  { $lookup: {
      from: "questions",
      localField: "_id",
      foreignField: "survey_id",
      as: "questions"
  }},
  { $project: { questions: { $sortArray: { input: "$questions", sortBy: { order: 1 } } } } }
])
```

### 8.2 单选题统计（每个选项多少人选）

```javascript
db.answers.aggregate([
  { $lookup: { from: "questions", localField: "question_id", foreignField: "_id", as: "q" } },
  { $unwind: "$q" },
  { $match: { "q.survey_id": ObjectId("..."), "q.type": "single" } },
  { $group: { _id: "$value", count: { $sum: 1 } } },
  { $sort: { count: -1 } }
])
```

### 8.3 多选题统计（每个选项被选次数）

```javascript
db.answers.aggregate([
  { $match: { "q.type": "multi" } },     // 先 match question 类型
  { $unwind: "$value" },                  // 数组展平
  { $group: { _id: "$value", count: { $sum: 1 } } }
])
```

### 8.4 数字题平均值

```javascript
db.answers.aggregate([
  { $lookup: { from: "questions", localField: "question_id", foreignField: "_id", as: "q" } },
  { $unwind: "$q" },
  { $match: { "q.survey_id": ObjectId("..."), "q.type": "number" } },
  { $group: { _id: "$q._id", avg: { $avg: "$value" }, n: { $sum: 1 } } }
])
```

### 8.5 某道题库题目被哪些问卷使用（需求六）

```javascript
db.questions.aggregate([
  { $match: { "bank_ref.root_id": ObjectId("...") } },
  { $lookup: { from: "surveys", localField: "survey_id", foreignField: "_id", as: "survey" } },
  { $project: { survey_id: 1, survey: { $arrayElemAt: ["$survey", 0] }, version: "$bank_ref.version" } }
])
```

### 8.6 单道题库的跨问卷统计（需求八）

```javascript
db.questions.aggregate([
  { $match: { "bank_ref.root_id": ObjectId("...") } },   // 1. 找到所有引用该题家族的问答题
  { $lookup: { from: "answers", localField: "_id", foreignField: "question_id", as: "a" } },
  { $unwind: "$a" },
  { $group: { _id: "$a.value", count: { $sum: 1 } } },   // 2. 汇总所有问卷的回答
  { $sort: { count: -1 } }
])
```

## 9. 数据生命周期与一致性

- **创建问卷**：状态 `draft`，无 `token`，无 `published_at`。
- **发布问卷**：生成 `token`、写入 `published_at`，状态转 `published`。
- **关闭问卷**：状态转 `closed`，填写接口直接拒绝。
- **过期**：提交时校验 `deadline`；过期返回 410；不主动改状态（便于区分"到期"与"被关闭"）。
- **删除问卷题目**：第二阶段支持删除问卷中的题目（软删除 `deleted_at`）。
- **删除题库版本**：软删除，并要求该版本**未被任何问卷引用**，否则返回 422。

### 9.1 题库题目的一致性规则（第二阶段）

| 场景 | 数据变化 | 保证 |
|---|---|---|
| 修改题库题目 | `bank_questions` 插入新版本文档 | 旧版本文档不动 → 旧问卷内容不变（需求三） |
| 问卷从题库选题 | `questions` 插入快照 + `bank_ref` | 题库再改也不影响该问卷 |
| 问卷切换题库版本 | 更新该问卷题目的快照 + `bank_ref.version_id` | 只影响这一份问卷（需求五） |
| 恢复历史版本 | 以旧版本内容**新建**一个版本 | 历史不被抹掉（需求四） |
| 删除题库版本 | 软删除 `deleted_at` | 已被问卷引用时拒绝删除 |
| 跨问卷统计 | 按 `questions.bank_ref.root_id` 聚合 `answers` | 只统计真正引用该题的问卷（需求八） |

---

## 10. 容量与边界

- 单文档大小上限 16MB 远大于本系统任何问卷与单次答案，无拆分需求。
- `answer_path` 长度受题目数量限制（第一阶段假定不超过 100 题）。
- 同一问卷最大提交量无硬上限，按索引与聚合管道性能自然伸缩。
